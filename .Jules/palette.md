## 2026-08-02 - [Wali Kelas Dashboard Accessibility Enhancements]
**Learning:** Custom styled interactive elements like file upload labels overlaying avatar images are often completely inaccessible to keyboard users and screen readers when inner elements are hardcoded with the `hidden` class. Replacing `hidden` with Tailwind's `sr-only` class on file inputs preserves keyboard accessibility, and using container classes like `focus-within:ring-2` and `group-focus-within:opacity-100` allows the overlay to become visible when focused, enabling keyboard navigation. Icon-only buttons also require explicit `aria-label` and `focus-visible:` focus styles to ensure screen reader users can identify their function and keyboard users can track their visual state.
**Action:** Always replace pure `hidden` interactive inputs with accessible alternatives like `sr-only`, utilize container-level `focus-within:` and `group-focus-within:` triggers for styled overlays, and supply explicit `aria-label` with `focus-visible:` indicators to icon-only buttons.
